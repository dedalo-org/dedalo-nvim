1. INTRODUCTION                                          *dedalo-introduction*

Dedalo turns git merges into contributor payouts. This plugin shows, next to
the lines in front of you, who earns from them.

It reads the same history a payout is computed from: `git blame` says who
wrote each line, `dedalo contributors` says what each author's work is worth,
and `dedalo identity list` says whether that author has a wallet on file.

The third one is why this is an editor plugin rather than a report. An author
with a contribution score and no wallet lands in a payout plan's `unresolved`
list and is paid nothing. Until now the only way to notice was to read the
plan. Now it is on the line.

==============================================================================
2. REQUIREMENTS                                          *dedalo-requirements*

  - Neovim 0.10 or newer
  - `git` on $PATH
  - `dedalo` on $PATH — https://github.com/dedalo-org/dedalo
  - a repository with a `dedalo.toml`

`:checkhealth dedalo` checks all four and says which is missing.

==============================================================================
3. SETUP                                                        *dedalo-setup*

Calling |dedalo.setup()| is optional; the defaults work. >lua

    require("dedalo").setup({
      -- Executable to run. Looked up on $PATH.
      cmd = "dedalo",

      -- Annotate every buffer in a Dedalo project on open. Off by default:
      -- a plugin that shells out to git blame on every BufEnter without
      -- being asked is a plugin people uninstall.
      auto_attach = false,

      -- Hide a share below this, in per cent. The author is still shown.
      min_share = 0.1,

      -- "eol", "right_align" or "inline".
      virt_text_pos = "eol",
    })
<
Pin the plugin to a tag rather than to `main`. `main` is where work lands;
a tag is a commit somebody decided was good.

Run |:checkhealth| `dedalo` afterwards. It reports this plugin's version and
checks Neovim's, `git`, the `dedalo` executable *and its version*, the
repository, and `dedalo.toml`, naming the one that is missing. It is the first
thing to run when the annotation is blank, and the first thing to paste into a
bug report.

The version is also `require("dedalo").version`.

==============================================================================
4. CONFIGURATION                                               *dedalo-config*

Every key, with its default.

                                                          *dedalo-config-cmd*
cmd ~
        Default: `"dedalo"`
        The executable to run. A bare name is looked up on `$PATH`; an
        absolute path is used as given.

                                                  *dedalo-config-auto_attach*
auto_attach ~
        Default: `false`
        Annotate a buffer as soon as it is opened in a Dedalo project, on
        `BufReadPost` and `BufWritePost`. Read |dedalo-cost| before turning
        this on.

                                                  *dedalo-config-debounce_ms*
debounce_ms ~
        Default: `150`
        Quiet period before an auto-attach fires, in milliseconds. `0`
        attaches immediately. Only used when |dedalo-config-auto_attach| is
        on.

                                                    *dedalo-config-min_share*
min_share ~
        Default: `0.1`
        Hide the percentage below this many per cent. The author is still
        shown; only the number is dropped, because below a tenth of a per
        cent it says nothing.

                                                *dedalo-config-virt_text_pos*
virt_text_pos ~
        Default: `"eol"`
        Where the annotation sits: `"eol"`, `"right_align"` or `"inline"`.

                                                   *dedalo-config-highlights*
highlights ~
        Default: `{ linked = "DedaloLinked", unlinked = "DedaloUnlinked",`
                 `  uncommitted = "DedaloUncommitted" }`
        Highlight group per state. See |dedalo-highlights|.

                                                        *dedalo-config-icons*
icons ~
        Default: `{ linked = "▏", unlinked = "▏", uncommitted = "▏" }`
        Prefix per state.

==============================================================================
5. COMMANDS                                                  *dedalo-commands*

                                                                     *:Dedalo*
:Dedalo [action]        Without an argument, toggles the annotation on the
                        current buffer.

                        attach    annotate this buffer
                        detach    remove the annotation
                        toggle    the default
                        refresh   forget the caches and annotate again
                        profile   what the last attach cost, in ms

                        Attribution and blame are both cached against the
                        commit at HEAD, so `refresh` is only needed after
                        something outside git changed — a
                        `dedalo identity link`, or an edit to `dedalo.toml`.

                        `profile` reports the last attach stage by stage. See
                        |dedalo-cost|.

The same are available as functions: >lua

    require("dedalo").attach()
    require("dedalo").detach()
    require("dedalo").toggle()
    require("dedalo").refresh()
    require("dedalo").profile()       -- string[], stage by stage
    require("dedalo").is_attached()   -- for a statusline
<

6. WHAT THE ANNOTATION SAYS                                *dedalo-annotation*

One annotation per run of consecutive lines by the same author, not one per
line. >

    ▏ ada · 50.0%
        Linked to a wallet. The share is of the contributor pool for the
        pending round — not an amount, because the size of the round is not
        decided yet.

    ▏ Bea · 50.0% — no wallet, would not be paid
        Has earned a share and has no wallet on file. This is the one worth
        acting on: `dedalo identity link`.

    ▏ bot — excluded from payouts
        Deliberately unpaid, by an `excluded` identity. Not a mistake, and
        not highlighted as one.

    ▏ Old — outside this round
        Blamed to somebody with no score in the pending range, usually
        because their work is already paid.

    ▏ uncommitted — earns nothing yet
        Not committed. Attribution reads merge history, so unsaved and
        uncommitted work is worth nothing until it lands.
<

7. WHAT IT COSTS                                                 *dedalo-cost*

The plugin shells out. Four commands run per attach. Median of five runs
against the Dedalo repository itself — 29 unpaid changes, a 700-line file: >text

    git rev-parse HEAD                1 ms
    dedalo contributors --json      118 ms   the whole cost, effectively
    dedalo identity list --json       3 ms
    git blame --line-porcelain       11 ms   proportional to the file
                                    ------
                                    133 ms   cold;  ~1 ms warm
<
Measure it on your own repository rather than trusting that: >vim

    :Dedalo attach
    :Dedalo profile
<
It runs only when asked — |:Dedalo|, `:Dedalo attach`, `:Dedalo refresh`.
Not on `CursorHold`, not on `CursorMoved`, not on `TextChanged`. Moving the
cursor never costs anything.

With |dedalo-config-auto_attach| it also runs on `BufReadPost` and
`BufWritePost`, debounced by |dedalo-config-debounce_ms|. Those two events are
not chatty on their own; `:bufdo`, a session restore and holding `]q` through
a quickfix list are.

Two caches, both keyed on the commit at `HEAD`, because history is the only
thing that changes either answer: attribution per repository, and blame per
file. So the second buffer in a repository pays for `git blame` alone, and
reopening a file you already annotated costs nothing. `:Dedalo refresh` drops
both, for the things that happen outside git: `dedalo identity link`, or an
edit to `dedalo.toml`.

Nothing blocks. Every subprocess goes through `vim.system()` with a callback,
so a slow repository makes the annotation appear late rather than making
Neovim stop.

The cost that scales badly is `dedalo contributors` on a long unpaid range: it
reads every landed change since the last settled round, which on a project
that has never settled is the whole history. The 118 ms above is a project
with 29 of them. That is a property of Dedalo rather than of this plugin.

If that is your situation, leave |dedalo-config-auto_attach| off and run
|:Dedalo| when you want it. The first attach pays; every one after it is
cached until the next commit.

    DedaloLinked         -> Comment

<

9. TROUBLESHOOTING                                    *dedalo-troubleshooting*

Nothing appears~
Run `:checkhealth dedalo`. The usual causes are `dedalo` not on $PATH, or the
repository having no `dedalo.toml`.

Everything says "outside this round"~
Every merge in the range is already settled, so the pending round is empty.
`dedalo scan` shows what is pending.

A share looks wrong~
The share is of the *pending* round, computed from merges since the last
settlement. `dedalo contributors` prints the same numbers.
